2
Clean

Fill the gaps, drop duplicate rows, and normalise city names — trailing spaces and inconsistent casing would otherwise split one city into several during a groupby.

02_clean.py
# fill the two gaps
df["Customer_Name"] = df["Customer_Name"].fillna("Unknown")
df["Profit"] = df["Profit"].fillna(df["Profit"].mean())

# remove exact duplicate rows
df = df.drop_duplicates()

# normalise city text: " chicago " -> "Chicago"
df["City"] = df["City"].str.strip()
df["City"] = df["City"].str.title()

df.isnull().sum()   # every column now 0

SQL case study

MySQL Workbench · schema, filtering, aggregation, grouping

1
Create the database and tables

Started from an empty server: create the schema, then define the products and orders tables with typed columns and a primary key on each.

01_schema.sql
CREATE DATABASE apex_retail;
USE apex_retail;

CREATE TABLE orders (
    Order_ID       INT PRIMARY KEY,
    Customer_ID    VARCHAR(20),
    Order_Date     DATE,
    City           VARCHAR(50),
    State          VARCHAR(10),
    Region         VARCHAR(20),
    Category       VARCHAR(50),
    Sub_Category   VARCHAR(50),
    Quantity       INT,
    Unit_Price     DECIMAL(10,2),
    Discount_Pct   INT,
    Total_Sales    DECIMAL(10,2),
    Payment_Mode   VARCHAR(20),
    Returned       VARCHAR(3)
);
2
Filter

Single conditions first, then combined logic with AND, OR and NOT — including parentheses, which change the result when AND and OR appear in the same clause.

02_filtering.sql
SELECT Order_ID, City, Region
FROM orders WHERE Region = 'West';

SELECT Order_ID, Total_Sales
FROM orders WHERE Total_Sales > 3000;

-- the brackets matter
SELECT Order_ID, Category, Total_Sales
FROM orders
WHERE Category = 'Clothing'
  AND (Total_Sales > 3000 OR Returned = 'Yes');

-- pattern, range and set matching
SELECT Order_ID, City
FROM orders WHERE City LIKE 'P%';

SELECT Order_ID, Region
FROM orders
WHERE Region IN ('East', 'Midwest');
3
Introduce NULLs deliberately

Set two rows' Region to NULL, then query for them. NULL isn't a value you can match with = — it needs IS NULL.

03_nulls.sql
UPDATE orders SET Region = NULL
WHERE Order_ID IN (1003, 1010);

SELECT Order_ID, City, Region
FROM orders WHERE Region IS NULL;

SELECT Order_ID, City, Region
FROM orders WHERE Region IS NOT NULL;
4
Aggregate — and the count that didn't match

Two counts on the same table, run one line apart, returning different numbers.

04_aggregate.sql
SELECT COUNT(*) FROM orders;
-- every row

SELECT COUNT(Region) FROM orders;
-- fewer: NULLs are skipped

SELECT SUM(Total_Sales) FROM orders;
SELECT AVG(Unit_Price) FROM orders;
SELECT MIN(Total_Sales), MAX(Total_Sales)
FROM orders;
WHAT THE COUNT CAUGHT

COUNT(*) counts rows. COUNT(Region) counts non-NULL values in that column — so the two NULLs set earlier are silently skipped. Same table, same moment, two different answers, and no warning. Anything averaged or divided by the wrong one is quietly wrong.

5
Group and rank

Grouping by one column, then by two, with sorting and limiting to pull top-N results.

05_grouping.sql
SELECT Category, COUNT(*) AS NumOrders
FROM orders
GROUP BY Category;

SELECT Category,
       COUNT(*) AS NumOrders,
       AVG(Total_Sales) AS AvgSale
FROM orders
GROUP BY Category, Region
ORDER BY Category, Region;

-- top 5 orders by value
SELECT Order_ID, City, Total_Sales
FROM orders
ORDER BY Total_Sales DESC
LIMIT 5;
6
Turn numbers into business language

CASE statements to tier sales and discounts, and a CASE inside ORDER BY to sort categories by business priority rather than alphabetically.

06_case.sql
SELECT Order_ID, Total_Sales,
    CASE
        WHEN Total_Sales >= 5000 THEN 'High Value'
        WHEN Total_Sales >= 2000 THEN 'Medium Value'
        ELSE                          'Low Value'
    END AS SaleTier
FROM orders;

-- order matters: '= 0' must come before '<= 10'
SELECT Order_ID, Discount_Pct,
    CASE
        WHEN Discount_Pct =  0 THEN 'No Discount'
        WHEN Discount_Pct <= 10 THEN 'Low Discount'
        ELSE                        'High Discount'
    END AS DiscountTier
FROM orders;
